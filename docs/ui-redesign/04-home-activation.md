# UI 04: ホーム未選択時の価値訴求と導線

## 状態

実装・検証完了

## 依存関係

- UI 03

## 目的

自分の武将が未選択のときに生じる大きな空白を解消し、初回ユーザーがサービスの価値と次の行動を理解できるようにする。

## 現状分析

### 良い点

- 見出し、保存範囲の説明、検索の順が単純で、選択操作自体は理解しやすかった。
- 候補は対象の期に登場した武将に限定され、部分一致、日本語順、最大12件に抑えられていた。
- 選択済みホームには、通算成績、年別推移、直近5戦がまとまっていた。

### UX / UI課題

- 未選択画面は検索フォーム以外が大きな空白になり、選択後に何が分かるのか伝わりにくかった。
- 武将を選ばずに使えるランキングと戦闘履歴への導線が、サイドバーだけに依存していた。
- 候補と入力の関係が支援技術へ伝わらず、矢印キー、Enter、Escapeによる候補操作もできなかった。
- 該当なしの表示に、表記や対象期を確認する回復方法がなかった。

## 変更内容

### 未選択画面

- 検索を主行動とし、「武将ランキングを見る」「戦闘履歴を見る」を補助行動にした。
- 通算成績、年別推移、最近の戦闘という選択後の価値を3項目でプレビューした。
- Desktopは説明と検索を2列、720px以下は1列、480px以下は補助ボタンを縦積みにした。
- 既存トークンと共通アイコンだけを使用し、Light / Darkの両テーマへ対応した。

### 検索操作

- 既存の部分一致、並び順、最大12件を純粋関数として分離し、テストで固定した。
- `combobox`、`listbox`、`option`、候補件数のlive statusを関連付けた。
- 入力欄では上下矢印とEnter、候補では上下矢印、Home、End、Escapeを利用できる。
- 該当なしでは、武将名の表記または対象の期を確認する回復方法を表示する。
- 選択後はダッシュボード見出し、変更開始後は検索、キャンセル後は変更ボタンへフォーカスを戻す。
- 矢印で選択中の候補をスクロール領域内へ追従させ、検索クリア後も入力へフォーカスを戻す。

### 構成

- `HomeActivation.tsx` に初回案内と検索UIを分離した。
- `homeSearch.ts` に候補抽出と候補位置の移動を分離した。
- `SearchBox` にはHomeだけが使う任意のref、キーボード、ARIA属性を追加した。
- Vitestで `@/` の既存importを解決できるようにし、HomeのSSR回帰テストを追加した。

## 変更理由

- 初回ユーザーへ「何を選び、選ぶと何が分かるか」を最初の画面内で伝えるため。
- 主行動と補助行動を3つ以内に保ち、Hickの法則に沿って判断負荷を抑えるため。
- キーボードとスクリーンリーダーでも、候補の存在、件数、現在位置、空状態を理解できるようにするため。
- 初回案内を選択済みダッシュボードから分離し、今後の変更範囲を限定するため。

## 互換性

- Cookie名 `onore_my_warlord`、保存属性、保存・復元方法は変更していない。
- 対象期のログから候補を作る仕様、trim後の部分一致、日本語順、最大12件を維持した。
- 選択済みホームの集計、グラフ、直近5戦、ウォッチリスト、詳細導線は変更していない。
- 保存済み武将が対象期に不在でもCookieを削除せず、従来の「この期に戦績がない」表示を維持する。
- 補助導線は既存の `selectTab("metrics")` / `selectTab("history")` を使い、選択期を保ったまま既存URLへ遷移する。
- 新しいAPI、依存関係、データ保存キーは追加していない。

## Before / After

### Before

- 未選択時は説明と検索だけで、その後の価値や代替導線が見えなかった。
- 候補はTab移動とクリックでは選べたが、検索候補としてのARIA関係と矢印操作がなかった。

### After

- 最初の画面内で、価値説明、武将検索、選択後のプレビュー、2つの補助導線を確認できる。
- 320pxからDesktopまで同じ情報順序を保ち、狭い画面では自然に1列へ変わる。
- 候補、該当なし、フォーカス移動に一貫したフィードバックがある。

比較画像は `docs/ui-redesign/ui-04-after/` に保存した。

## 検証結果

- 既存基準: 25ファイル / 307テスト成功。
- 追加対象テスト: 4ファイル / 14テスト成功。
- 実ブラウザ:
  - 候補表示、上下矢印、Enter選択、Escapeでの解除。
  - Cookie保存、再読込後の復元、変更キャンセル。
  - 該当なしと回復文言。
  - `/ranking`、`/history` へのSPA遷移。
  - 1440px Light / Dark、900px Light、500px Lightの画像比較。
  - 320pxで `scrollWidth === viewport width`。
  - 8件の候補で末尾を選択した際、`scrollTop > 0` かつactive optionが表示領域内にあること。
- 全体テスト: 29ファイル / 321テスト成功。
- Lint: 警告・エラーなし。
- 型チェック: 成功。
- production build: 成功（全10静的ページ生成、全routeのbuild完了）。

## 残っているリスク

- 実DOM操作テストの依存関係は追加していないため、フォーカス移動はChromeでの手動相当確認に残る。
- 既存のTabによる候補選択を維持しつつ `aria-activedescendant` も追加している。VoiceOver / NVDAの実機読み上げ順は、後続のWCAG監査PRでも確認する。
- 「最近選択した武将」の履歴データは既存仕様に存在しない。新しい保存キーを追加せず、今回は表示していない。

## ロールバック

`HomeActivation` の未選択分岐だけを従来の検索表示へ戻せる。Cookie、集計、選択済み画面にはロールバック差分が及ばない。
