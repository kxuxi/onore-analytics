# UI 07: 詳細画面テンプレート

## 状態

全体調査・実画面基準取得済み／実装前

## 依存関係

- UI 06

## 目的

武将、兵種、武器、品物、国で異なる詳細画面の構造を、共通の見出し、主要指標、Section、空状態へ揃える。

## 変更対象

- `DetailPage`による外枠と見出しの意味付け
- `DetailSummary`による主要指標と勝敗バーの共通化
- `DetailEmptyState`によるタイトル・説明付き空状態の共通化
- `DetailBattleLogSection`による最近の戦闘枠の共通化
- 320pxでもタイトルを潰さないレスポンシブヘッダー
- 推移グラフのデータに基づく文章要約

## 対象外

- 詳細URL、集計値、グラフ計算、関連項目の順序
- API、DB、ブラウザ履歴スタックの仕様
- Sectionの開閉状態、年フィルターの適用範囲、表示件数
- 管理者限定機能と兵種編集の権限制御

## 互換条件

- すべての詳細URLと既存共有リンクを維持する
- 表示する値、母数、並び順を変更しない
- 戻る操作と相互リンクの挙動を維持する
- 武器は`equip2`、品物は`equip1`を集計する内部互換を維持する
- 武将と他4種で異なる両陣営一致時の計上方法を維持する
- 武将だけが使用兵種と戦闘ログで年フィルターを共有する挙動を維持する

## 調査結果

- 5種の詳細画面は、武将、兵種、武器・品物共通、国の4コンポーネントで実装されている
- `DetailHeader`、`StatCards`、`WinRateBar`、`Section`、`BattleLogList`は既に共通化されている
- 未共通なのは外枠＋ヘッダー、主要指標＋勝敗バー、空状態、戦闘ログSectionである
- 1440pxの代表画面は横方向の破綻がなく、既存の読書幅と情報密度を維持できる
- 320pxの兵種詳細では、戻る・タイトル・編集・共有を1行に置くためタイトル領域が44pxまで縮み、4文字の兵種名が3行になる
- 詳細内の「戻る」は`window.history.back()`ではなく内部`detailStack`を1件減らす操作である
- URLは現在の詳細だけを表し、相互遷移の途中履歴は`history.state`にのみ保持される
- 武将、兵種、国には固有状態・権限制御・非同期取得があり、Section配列への設定駆動化は責務を曖昧にする

## 変更理由

既存UIの良い点である情報量、固有分析、読書幅を維持しながら、同じ見た目を各画面が個別に組み立てる重複を減らす。狭幅では操作を最初の行、現在地を次の行へ分け、タイトルを読むための幅を確保する。集計や画面固有状態は共通部品へ移さず、共通化の責務を表示構造だけに限定する。

## 期待する効果

- 5種で外枠、戦績サマリー、空状態、最近の戦闘の見出し階層が揃う
- 空状態や主要指標を追加・修正する際の変更箇所が減る
- 320pxでも詳細名を自然な幅で読める
- グラフを視覚だけに依存せず、データの開始・終了・最大値を文章で把握できる
- 各詳細画面は固有の集計・関連項目・管理操作に集中できる

## 影響範囲

- `components/detail/DetailParts.tsx`
- `components/detail/WarlordDetail.tsx`
- `components/detail/UnitDetail.tsx`
- `components/detail/EquipDetail.tsx`
- `components/detail/FactionDetail.tsx`
- 推移グラフを持つ`UnitInsights.tsx`と`WarlordInsights.tsx`
- 詳細画面に限定したCSSと回帰テスト

## 実施順

1. 5種のURL往復、旧共有リンク、武器・品物の内部対応を回帰テストで固定する
2. 共通外枠、戦績サマリー、空状態、戦闘ログSectionを追加する
3. 固有状態の少ない武器・品物から、兵種、国、武将の順に移行する
4. 320px以下を含むヘッダーのレスポンシブ配置を整える
5. 推移グラフの既存計算値から文章要約を生成する
6. 値、Section順、件数、URL、戻る、相互リンクを変更前後で比較する

## 受入条件

- 5種類の詳細画面で同じ情報階層を利用する
- 主要指標は既存の4〜5件と同じ値・順序を保つ
- 見出し階層が現在の詳細種別と名前を正しく示す
- 欠損・空状態が同じDOM構造と視覚言語を利用する
- 320pxでタイトルが操作群に押し潰されず、横スクロールが発生しない
- 推移グラフにデータ内容を説明するアクセシブルネームがある

## 確認方法

- 各詳細種別の代表データと空状態
- URL直アクセス、相互遷移、戻る操作
- 変更前後の値・順序比較
- 320 / 390 / 768 / 1024 / 1440pxの実画面比較
- 5種のパスと旧クエリの回帰テスト
- 集計・Lint・型チェック・本番ビルド

## リスク

- 戻るボタンをブラウザ履歴へ置換すると、詳細内の相互遷移履歴が変わる
- 共通部品へ`key`を付けると、同種別の対象切替時にSection等のローカル状態がリセットされる
- 年フィルターを一律化すると、武将と他4種で現在異なる適用範囲が変わる
- 「1戦闘1件」へ統一すると、兵種・武器・品物・国の両側一致時の件数が変わる
- 武器・品物の内部列対応を一般化すると、既存データの意味が逆転する
- パンくずから履歴途中へ直接遷移させるには、現行URLにない状態の公開仕様化が必要になる

## ロールバック

共通テンプレートを各詳細画面の既存構造へ戻す。statsとAPIには触れない。
