# UI 06: 戦闘履歴の情報階層

## 状態

実装・ローカル検証完了（Draft PR）

## 依存関係

- UI 05

## 目的

戦闘履歴カードの重複情報と縦方向の長さを減らし、勝敗、日時、参加者を最初に読み取れるようにする。

## 変更対象

- 勝敗、日時、主要参加者を第一階層へ再配置
- 場所、勢力、装備、補助情報の第二階層化
- Mobileでの詳細展開
- 勝敗の色以外の表現
- 履歴フィルター結果件数との統合

## 対象外

- 履歴の件数、並び順、勝敗判定、参加者、保存形式
- コピー内容、削除対象ID、管理者認可

## 互換条件

- 現在表示される全情報へ到達できる
- 既存の検索・期間・国フィルター結果を維持する
- 履歴カードからの武将・兵種詳細遷移を維持する
- 現状存在しない国詳細遷移や履歴編集機能は追加しない
- URLのコピー・外部表示、管理者の個別削除・表示ページ一括削除を維持する

## 実施順

1. 重複排除・検索・期間・並び順を純粋関数へ分離し、現行挙動をテストで固定する
2. 履歴カードを表示専用コンポーネントへ分離する
3. 勝敗・日時・参加武将を第一階層へ移し、補助情報を第二階層へ整理する
4. 同一DOMのまま、狭幅では補助情報を開閉可能にする
5. 自動テストと320 / 390 / 768 / 1024 / 1440pxの実画面で互換性を確認する

## リスク

- 同一内容の履歴は最初のレコードと削除IDを保持しており、重複排除順を変えると削除対象が変わる
- 日時不明の履歴は昇順・降順とも末尾であり、一般的な比較関数への置換で順番が変わり得る
- 一括削除は検索結果全体ではなく、現在ページの最大20件だけが対象
- カード余白の外部リンク操作と、カード内ボタンのイベント伝播を分離する必要がある

## 受入条件

- 主要情報がカード冒頭で認識できる
- 二次情報へ1操作以内で到達できる
- Mobileカードの重複表示と平均的な高さが減る
- スクリーンリーダーの読み上げ順が視覚順と一致する

## 確認方法

- 変更前後の代表履歴データ比較
- 履歴フィルター単体テスト
- 勝敗、撤退、欠損データ、管理操作の手動確認

## ロールバック

新しいカード表示だけを既存の履歴マークアップへ戻し、集計・フィルター処理は維持する。

## 実装結果

### 変更内容

- 重複排除、検索、期間、勢力、並び順の処理を `lib/historyFilters.ts` の純粋関数へ分離した
- 履歴カードを `BattleHistoryCard` へ分離し、勝敗、日時、参加武将を第一階層へ整理した
- 場所、戦闘番号、ターン、勢力、兵種、兵種タイプ、品物、武器、対矢を第二階層へ整理した
- 720px以下では第二階層を「詳細を表示」で開閉し、それより広い画面では常時表示する構成にした
- カード全体の外部リンク、URLコピー、管理者削除、武将・兵種への既存遷移を維持した
- 旧カード固有の `.battle-card` / `.bc-*` スタイルと、未使用の `mark.hl` を削除した
- 純粋関数とカードのSSR構造に回帰テストを追加した
- 320 / 390 / 768 / 1024 / 1440pxの実画面を `docs/ui-redesign/ui-06-after/` に保存した

### 変更理由

旧カードでは勝者名が複数箇所に現れ、主要情報と装備等の補助情報が同じ強さで並んでいた。そのため、一覧で勝敗と対戦相手を比較する際の視線移動とカード高が大きかった。表示責務と抽出・並び替え責務も同じコンポーネントに集中していたため、現行挙動をテストで固定したうえで分離した。

### 互換性

- 公開API、URL、DBスキーマ、環境変数、保存形式は変更していない
- `battleKey` が同じ履歴は従来どおり入力順で最初のレコード、ID、URLを採用する
- 期間境界、欠損日時、同一日時、単独月指定を含む検索・フィルター・並び順をテストで固定した
- 1ページ20件、現在ページだけを対象にする一括削除、個別削除の確認文と対象IDを変更していない
- カード余白から開くURL、URLコピー文字列、武将名・兵種名からの遷移値を変更していない
- 既存情報は削除せず、狭幅では1操作で第二階層へ到達できる

### 検証結果

- `npm test`: 34ファイル、352テスト成功
- `npm run lint`: 警告・エラーなし
- `npm run typecheck`: 成功
- `npm run build`: Next.js本番ビルド成功、全10静的ページ生成成功
- `git diff --check`: 成功
- 320 / 390 / 768 / 1024 / 1440pxで横スクロールが発生しないことを確認
- 共有DBの15,032件に対し、各幅で先頭20件と並び順が一致することを確認
- 検索、勢力、並び順、カードリンク、URLコピー、詳細開閉を実ブラウザーで確認
- モバイルの主要操作領域が44px以上、キーボードフォーカスが視認可能であることを確認
- 設定済み・フォールバックを含む参加者色をLight / Dark双方で全件検査し、文字コントラストの最小値がLight 4.89:1、Dark 6.30:1であることを確認

### 残っているリスク

- 認証済み管理者による削除は共有データを変更するため実行しておらず、対象ID・確認文・API呼び出しの静的確認までとしている
- 1024pxで極端に長い武将名は2行になるが、情報欠落と横スクロールは発生しない
- 320pxでヘッダーのブランド名が省略される既存課題は本作業の対象外で、後続のレスポンシブ／アクセシビリティ作業へ残す
- カード内操作の自動イベントテストは追加しておらず、SSR構造テストと実ブラウザー確認で補っている

## Before / After

- 390pxの代表カード高は約290pxから約177〜181pxへ減少し、補助情報は必要時に展開できる
- 1440pxの代表カード高は約161pxから約123pxへ減少した
- 変更前は勝敗、参加者、装備が混在していたが、変更後は「勝敗 → 日時・操作 → 対戦者 → 補助情報」の順で読める
- 勝者を色だけでなくトロフィー、太字、文脈付きラベルでも識別できる
- 狭幅用と広幅用の情報を二重に持たず、同一DOMをCSSと開閉状態で適応させた
