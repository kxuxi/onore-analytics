# UI 03: 共通フィルターと適用状態表示

## 状態

実装済み・検証済み

## 依存関係

- UI 02

## 目的

履歴、ランキング、図鑑で重複している検索・フィルターUIを統一し、現在の絞り込み条件と結果件数を見失わないようにする。

## 変更対象

- `FilterPanel`、`ActiveFilterChips`、結果件数表示
- 検索、期間、最低回数、武将タイプ、兵種タイプの共通表示規則
- 条件の個別解除と一括解除
- 履歴、武将ランキング、兵種・武器・品物ランキング、図鑑への適用

## 対象外

- フィルター選択肢、初期値、集計方法、並び順の変更
- APIでのサーバーサイド検索への置き換え

## 互換条件

- 全期間、最低10回など現在の初期条件を維持する
- 絞り込み前後の対象レコードと順序を変更しない
- URLに保存済みの条件がある場合はその形式を維持する

## 受入条件

- 一覧と詳細で同じ条件が適用される
- 有効条件、結果件数、解除方法が常に認識できる
- すべてのラベルが入力要素と関連付けられる
- キーボードのみで条件設定と解除ができる

## 確認方法

- フィルターヘルパーの単体テスト
- 変更前後の件数・順序・代表値比較
- Desktop / Mobileの操作確認

## ロールバック

共通表示部品を外し、各画面の既存stateとフィルターロジックはそのまま再接続する。

## 変更内容

- `components/FilterPanel.tsx`: 検索、開閉、全解除、適用条件、結果件数の共通シェルを追加
- `ActiveFilterChips`: 適用中の副条件を個別解除できるボタンとして表示
- 武将ランキング、兵種・武器・品物ランキング: 全期間・最低10回の既定値を維持して適用
- 戦闘履歴: 検索、並び順、国、年月、日付、一括削除を同じ操作順へ整理
- 兵種・武器・品物図鑑: 重複していた件数表示を共通結果表示へ統合
- 武将ランキングの各指標カード: 指標ごとの正確な対象人数を表示
- 展開中は「閉じる」、一括操作は「条件を解除」と表示して操作結果を明確化
- 条件の個別解除後は次の条件、全解除後はフィルタートグルへフォーカスを復元
- 兵種図鑑の取得中は0件ではなく「兵種を読み込み中…」と通知
- `FilterPanel` の見出し、開閉、関連付け、status、解除ラベルを6件のSSRテストで固定

## 変更理由

検索欄、フィルターボタン、解除、入力項目、件数が画面ごとに異なる位置へ置かれていたため、
同じ順序と操作規則へ揃えました。検索欄で常に確認できる検索語と、期間タブで常に確認できる
集計期間はチップへ重複表示せず、閉じると見えなくなる副条件だけをチップにします。

## 互換性

- state、絞り込みpredicate、並び順、同順位時の規則、選択肢は各タブ内に維持
- ランキングの初期値は全期間・最低10回・フィルター展開済みを維持
- 期間と詳細指標は従来どおり全解除の対象外
- 戦闘履歴の全解除は並び順を維持
- 兵種図鑑の全解除は並び順とサイドバーで選択した期を維持
- 武器・品物図鑑の全解除は従来どおり並び順を使用回数順、最低回数を1へ戻す
- URL、API、DB schema、環境変数、タブキー、表示する集計値は変更していない

## 残っているリスク

- 管理者向け一括削除は表示位置のみの変更で、実削除は安全のため手動実行していない
- 390px実端末とキーボード操作は、Preview環境でも追加確認する
- 集計期間を全解除に含める変更は既存挙動を変えるため実施していない
- 対象外タブが利用する既存 `.filter-grid` / `.search-row` はCSS分割PRまで維持する
